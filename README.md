## 1. Цель работы

Цель лабораторной работы — реализовать полный цикл работы агента обучения с подкреплением: обучить политику PPO в симуляторе, сохранить её, предоставить действие через HTTP API и вести журнал взаимодействий. Одностраничная веб-панель содержит живую сцену CartPole: на каждом шаге серверная политика выбирает действие, среда возвращает новое физическое состояние и награду, а canvas плавно отображает движение. В этой же панели доступны состояние сервиса, журнал действий, оценка качества и кандидатное обучение.

## 2. Вариант

| Параметр | Значение |
|---|---|
| Среда | `CartPole-v1` (Gymnasium) |
| Seed | `116` |

| Режим выбора действий | `greedy` — детерминированный выбор действия с максимальным логитом |

| Минимальная версия Python | `3.10` |

## 3. Ограничение эксперимента

Обучение и оценка выполняются **только в симуляторе Gymnasium CartPole-v1**. Реальные пользователи, реальные объекты, производственные системы и персональные данные в эксперименте не используются. Модель получает числовое состояние симулятора и выбирает одно из двух действий: 0 — влево или 1 — вправо.

## 5. Установка и запуск

Рекомендуется Python 3.11.9 или другая версия не ниже 3.10, для которой доступны колёса PyTorch и NumPy. Все зависимости зафиксированы по версиям. Обучение использует CPU-версию PyTorch.

### Windows 11 / PowerShell

Выполните команды из корня репозитория:

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
python -m pip install -r requirements-train.txt
```

Если PowerShell запрещает активацию окружения, выполните команду в текущем окне PowerShell:

```powershell
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass
.\.venv\Scripts\Activate.ps1
```

Обучите модель. По умолчанию используется 100 000 шагов; обучение сохраняет SB3-архив и NumPy-веса, после чего автоматически проверяет их согласованность на 1 000 случайных состояний:

```powershell
python scripts/train.py
```

Чтобы задать число шагов или каталог результатов:

```powershell
python scripts/train.py --timesteps 150000 --out models
```

Оцените уже сохранённую модель. Этот скрипт **не переобучает** агента:

```powershell
python scripts/evaluate.py
```

Для установки только зависимостей веб-сервиса, без PyTorch и Stable-Baselines3:

```powershell
python -m pip install -r requirements.txt
```

Запустите веб-сервис:

```powershell
uvicorn app.main:app --host 127.0.0.1 --port 8000
```

Откройте в браузере `http://127.0.0.1:8000`. Интерактивная документация API доступна по адресу `http://127.0.0.1:8000/docs`.

Запуск тестов из корня проекта:

```powershell
python -m pytest -q
```

### Linux / macOS

python3 -m venv .venv

## 6. Живая симуляция в браузере

Главная страница — единая панель без перехода на отдельные страницы. Центральная сцена отрисовывается на `canvas`, но координаты не генерируются анимацией: браузер получает кадры у `/api/sim/step`. При наличии установленного Gymnasium сервер использует настоящую среду `CartPole-v1`. На каждом шаге загруженная NumPy-политика выбирает действие в режиме `greedy`, среда рассчитывает следующее состояние и награду, а успешное действие записывается в `logs/actions.jsonl`. Анимация только плавно интерполирует полученные состояния для отображения.

Вкладка «Управление» запускает, приостанавливает и сбрасывает эпизод. В режиме «Вручную» можно удерживать толчок влево или вправо и наблюдать, как меняется угол шеста. Клавиша `Space` запускает или приостанавливает эпизод, клавиша `R` сбрасывает его. Вкладки «Метрики» и «Обучение» работают внутри той же страницы. На небольших экранах интерфейс располагается вертикально, но остаётся одной HTML-страницей.

Пример запуска эпизода через HTTP (замените `demo-1` уникальным идентификатором своей сессии):

```bash
curl -X POST http://127.0.0.1:8000/api/sim/reset \
  -H "Content-Type: application/json" \
  -d '{"session_id":"demo-1","seed":116}'

curl -X POST http://127.0.0.1:8000/api/sim/step \
  -H "Content-Type: application/json" \
  -d '{"session_id":"demo-1","steps":4,"mode":"agent"}'
```

## 7. Примеры запросов API

Проверка состояния сервиса:

```bash
curl http://127.0.0.1:8000/health
```

Пример ответа:

```json
{
  "status": "ok",
  "model_version": "ppo-cartpole-v1.0",
  "model_loaded": true
}
```

Получение действия:

```bash
curl -X POST http://127.0.0.1:8000/act \
  -H "Content-Type: application/json" \
  -d '{"state":[0.01,0.2,-0.03,-0.4]}'
```

Пример ответа (конкретное действие зависит от загруженных весов):

```json
{
  "action": 0,
  "model_version": "ppo-cartpole-v1.0"
}
```

Можно передать награду предыдущего шага для журнала:

```bash
curl -X POST http://127.0.0.1:8000/act \
  -H "Content-Type: application/json" \
  -d '{"state":[0.01,0.2,-0.03,-0.4],"reward":1}'
```

## 8. Контракт API

| Метод | Путь | Вход | Успешный ответ | Основные коды ошибок |
|---|---|---|---|---|
| `GET` | `/health` | Нет | `status`, `model_version`, `model_loaded` | `500` при внутренней ошибке |
| `POST` | `/act` | `state`: ровно 4 конечных числа; необязательный `reward`: конечное число или `null` | **Ровно** `action`, `model_version` | `422` — ошибка валидации; `503` — политика не загружена |
| `GET` | `/` | Нет | HTML веб-панели | `404` — файл не найден |
| `GET` | `/api/logs?limit=10` | `limit` от 1 до 100 | `items`, `count` | `422` — неверный `limit` |
| `GET` | `/api/progress` | Нет | Состояние фоновой операции и признак `train_enabled` | `500` — внутренняя ошибка |
| `POST` | `/api/sim/reset` | `session_id`, необязательный `seed` | Начальное состояние, seed и тип среды | `422` — неверные параметры; `500` — не удалось создать среду |
| `POST` | `/api/sim/step` | `session_id`, количество шагов 1–8, режим `agent` или `manual`, для ручного режима действие 0/1 | Новые состояния, выбранные действия, награда, номер шага и флаг завершения | `404` — сессия не найдена; `422` — неверные параметры; `503` — политика не загружена |
| `POST` | `/api/sim/close` | `session_id` | `closed`: признак освобождения среды | `200` даже если сессия уже закрыта |
| `POST` | `/api/evaluate` | Пустое тело | `202`: `job_id`, сообщение | `409` — другая операция уже идёт; `503` — нет политики |
| `GET` | `/api/evaluate/result` | Нет | Последний сохранённый результат оценки | `404` — результатов пока нет |
| `POST` | `/api/train` | `timesteps`: от 5 000 до 50 000, по умолчанию 30 000 | `202`: `job_id`, сообщение | `403` — обучение отключено; `409` — другая операция; `422` — число шагов вне лимита; `503` — нет основной модели |

`POST /act` возвращает только два поля, `action` и `model_version`; служебная информация в ответ не добавляется. Некорректные значения `NaN` и `Infinity` отклоняются с кодом `422`. Если запись в журнал не удалась, корректное решение агента всё равно возвращается, а ошибка записывается в журнал сервера.

## 9. Журнал взаимодействий

Файл `logs/actions.jsonl` содержит одну JSON-запись на строку. Каталог создаётся автоматически. Время записывается в UTC в ISO 8601 с окончанием `Z`; добавление защищено `threading.Lock`, файл открывается в режиме добавления.

Пример строки:

```json
{"time":"2026-10-08T12:00:00Z","state":[0.01,0.2,-0.03,-0.4],"action":1,"reward":null,"model_version":"ppo-cartpole-v1.0"}
```

Поля: `time` — время запроса; `state` — четыре числовых значения; `action` — действие агента (`0` или `1`); `reward` — переданная награда или `null`; `model_version` — версия политики. Файл включён в репозиторий с несколькими демонстрационными записями. На бесплатном Render файловая система эфемерная, поэтому журнал после перезапуска или нового развёртывания может сбрасываться.

## 10. Результаты оценки

Результат последнего запуска хранится в `results/evaluation.json`. Оценка выполняется на 20 эпизодах для PPO и случайного агента. Для эпизода `i` используется `seed = 116 + i`; для PPO включён детерминированный выбор действия. Значение награды в CartPole равно количеству шагов эпизода (максимум 500). В таблице приведены значения из `results/evaluation.json` для включённой в проект NumPy-политики:

| Агент | Среднее | Std | Min | Max | Эпизодов |
|---|---:|---:|---:|---:|---:|
| PPO (greedy) | 500.00 | 0.00 | 500 | 500 | 20 |
| Random | 18.85 | 8.05 | 10 | 34 | 20 |

В этой контрольной оценке средняя награда PPO — 500 из 500, а средняя награда случайного агента — 18.85; отношение средних составляет **26.53 раза**. Результаты получены для seed 116–135. После переобучения они могут измениться. Скрипт `scripts/evaluate.py` не запускает обучение и не изменяет веса модели.

## 11. Воспроизводимость

Вариантные параметры централизованы в `config.py`. Обучение фиксирует `random.seed(116)`, `numpy.random.seed(116)`, `torch.manual_seed(116)`, seed среды и seed алгоритма PPO. Перед сохранением экспорта проверяется структура политики: два скрытых слоя `Linear → Tanh`, выходной линейный слой с двумя логитами. Затем на 1 000 состояниях, созданных генератором NumPy с seed 116, сравниваются действия SB3 и NumPy.

Используемые версии библиотек зафиксированы в `requirements.txt` и `requirements-train.txt`. Для проверки повторяемости выполните `python scripts/evaluate.py` повторно и сравните массивы `ppo.rewards` и `random.rewards` в `results/evaluation.json`: при неизменных весах и версиях зависимостей они должны совпасть. Поле `date` закономерно меняется между запусками.

## 12. Применимость RL

CartPole — задача управления с отложенной обратной связью: выбранное действие влияет на последующее состояние, а динамика тележки и шеста нелинейна. Однако для этой конкретной задачи полный RL избыточен по сложности и вычислениям: удерживать шест можно и простым правилом, например пропорциональным регулятором по углу и угловой скорости. Обучение с подкреплением становится полезнее, когда динамику сложно выразить точной формулой или поведение контроллера нужно получить из взаимодействия с симулятором. Симулятор позволяет безопасно проверять множество действий без риска повредить реальный объект. В этой лабораторной работе акцент сделан не на доказательстве превосходства PPO над простым регулятором, а на инженерном цикле работы политики. Этот цикл включает обучение, сохранение весов, экспорт в лёгкий формат, предоставление решения через API и регистрацию запросов. Таким образом, CartPole выступает компактным стендом для демонстрации архитектуры RL-сервиса.

## 13. Ограничения деплоя на Render Free

- Бесплатный веб-сервис может засыпать после бездействия, поэтому первый запрос иногда занимает заметно больше времени; интерфейс показывает состояние пробуждения и повторяет проверку `/health`.
- Файловая система эфемерная: `logs/actions.jsonl` и новые результаты могут потеряться при перезапуске или развёртывании. Постоянный диск не подключается.
- Ограничение бесплатного сервиса — небольшие вычислительные ресурсы (в частности, около 512 MB RAM и 0.1 CPU). Поэтому API использует NumPy-веса и не импортирует PyTorch или Stable-Baselines3 при обычном запуске.
- В `render.yaml` установлено `TRAIN_ENABLED=false`: так сайт не запускает тяжёлое обучение на бесплатном инстансе. Кнопка обучения показывает пояснение и неактивна. Локально обучение-кандидат можно включить переменной `TRAIN_ENABLED=true`; кандидат сохраняется в `models/candidate/` и не заменяет рабочую модель.
- При намеренном включении обучения на Render нужно убедиться, что зависимости обучения установлены, и учитывать ограничения по времени и памяти. Для надёжного бесплатного деплоя предпочтительно обучать модель локально и публиковать готовые файлы в `models/`.

## 14. Деплой на Render

В корне репозитория лежит `render.yaml`, использующий актуальные поля Blueprint: `runtime: python`, `plan: free`, `buildCommand`, `startCommand`, `healthCheckPath` и список `envVars`.

1. Отправьте проект в GitHub.
2. В Render выберите создание нового Blueprint и подключите репозиторий `SII-LR07-Nazdratenko`.
3. Проверьте, что Render нашёл `render.yaml` в корне, затем создайте ресурсы.
4. Дождитесь завершения сборки и успешной проверки `/health`.
5. Откройте URL сервиса и проверьте `GET /health`, `POST /act`, журнал и работу страницы после холодного старта.
6. Не включайте обучение на бесплатном сервере без необходимости; для демонстрации достаточно заранее обученной политики.

**Сайт после публикации:** `заполнить после успешного деплоя`.

## 15. Допущения

- Выбран Python 3.11.9 для Render, хотя проект совместим с Python 3.10 и выше; этот вариант соответствует закреплённым версиям библиотек.
- Основная модель может быть воспроизведена локально командой `python scripts/train.py`; скрипт создаёт нативно сохранённый архив SB3 и обновляет NumPy-веса. Предварительно включённые веса подходят для лёгкого API и имеют среднюю награду 500 из 500 на контрольных 20 эпизодах. После переобучения значения `results/evaluation.json` следует обновить через `python scripts/evaluate.py`.
- При подготовке архива в среде сборки установка Gymnasium и Stable-Baselines3 была недоступна из-за ошибки DNS. Поэтому здесь не удалось запустить `PPO.load` и подтвердить проверку согласованности с настоящей установкой SB3; ZIP проверен на целостность, а NumPy-веса — на форму, конечность и работу API. После установки `requirements-train.txt` рекомендуется выполнить `python scripts/train.py`, чтобы создать нативный SB3-архив и автоматически проверить совпадение 1 000 действий.
- Режим действий реализован как жадный выбор `argmax` по логитам выходного слоя политики, что эквивалентно `model.predict(observation, deterministic=True)` для этой дискретной политики.
- Кандидатное веб-обучение отключено на Render Free, но реализовано и может включаться переменной окружения. Оно не подменяет основную политику автоматически.
- Демонстрационные строки журнала генерируются тестовыми запросами к локальному API; после чистого клонирования могут отображаться последние образцы, а не история предыдущего запуска.
- Живая сцена использует Gymnasium `CartPole-v1`, если Gymnasium установлена. Для ограниченной офлайн-разработки без этой зависимости предусмотрен совместимый fallback с теми же уравнениями CartPole; обучение при этом всё равно выполняется только отдельным учебным скриптом в Gymnasium.
